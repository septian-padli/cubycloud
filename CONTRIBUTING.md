# Contributing

Thank you for considering a contribution to CubyCloud.

## Before you start

- For a bug report, include the affected route or operation, steps to reproduce, expected behavior, and actual behavior.
- For a larger feature, discuss the scope with the maintainers before investing in a broad implementation.
- Never include passwords, recovery keys, storage credentials, private file contents, or unredacted logs in an issue or pull request.

## Prepare a change

1. Create a focused branch from the current project branch.
2. Keep the change limited to one concern and update the relevant documentation.
3. Add or update tests for externally visible behavior.
4. Run the relevant checks from the [Development](docs/development.md) and [Testing](docs/testing.md) guides.
5. For UI changes, include a screenshot captured from the running application and avoid real user data.

## Pull requests

Describe the problem, the user-visible change, and the checks you ran. Call out database migrations, configuration changes, and known limitations explicitly. Do not bundle unrelated formatting or generated artifacts.

The repository currently has no license file. A project license has not been selected; contributors should be aware that reuse and redistribution terms are not yet defined.
